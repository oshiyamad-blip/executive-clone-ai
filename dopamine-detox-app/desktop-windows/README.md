# フォーカスロック（Windows）

PC でセッション中、**許可したアプリ以外を前面に出させない**常駐ツール。
スマホ側のデトックスアプリと同じ考え方の PC 版で、記録も同じ JSON 形式で残る。

想定している使い方は「YouTube Music と Word（または自作の脚本エディタ）だけで書く時間」。

## 動く仕組み

0.4秒ごとに「いま手前にあるウィンドウ」を調べ、許可リストに無ければ**最小化**する。

**プロセスは強制終了しない。** Word の未保存文書を巻き添えにするからで、
確実にブロックするより、失うものが無い方を選んでいる。

止められないようにはできていない。タスクマネージャーは常に許可してあるし、
HUD の「中断」ボタンでいつでも終われる。**これは鉄格子ではなく、無意識に手が伸びるのを
止めるための段差**だと思って使うこと。本当に破れなくしたければ、別の管理者アカウントか
Windows のポリシー機能（AppLocker など）が要る。

## 使い方

### 1. 許可したいアプリの名前を調べる

```
identify.cmd
```

（または `powershell -ExecutionPolicy Bypass -File .\detox-focus.ps1 -Identify`）

前面のアプリのプロセス名とウィンドウタイトルが流れるので、許可したいアプリに切り替えて
表示された名前を控える。いまの許可リストで通るかどうかも `[許可]` / `[ブロック]` で出る。

### 2. `allowlist.json` を書き換える

```json
{
  "allow": [
    { "label": "脚本エディタ", "process": "your-editor.exe" }
  ]
}
```

| キー | 意味 |
| --- | --- |
| `process` | プロセス名。`.exe` は付けても付けなくてもよい。**必須** |
| `titleContains` | ウィンドウタイトルにこれを含むときだけ許可。文字列か、その配列 |
| `titleNotContains` | 含むときは許可しない。`titleContains` より優先される |
| `label` | 表示用の名前。判定には使わない |
| `neverTouch` | 絶対に最小化しないプロセスの追加分（既定のものに足される） |

### 3. セッションを始める

```
detox-focus.cmd -Minutes 45
```

引数なしのダブルクリックなら30分。右下に残り時間の小さな窓（HUD）が出る。
許可外のアプリを開こうとすると、その窓が最小化され、HUD にアプリ名が出る。

`-DryRun` を付けると最小化せず、ブロック対象の表示だけをする。許可リストの確認用。

## YouTube Music を通すときの注意

**Chrome のタブで開いていると、`chrome.exe` を許可した時点でインターネット全部が許可になる。**

そうならないよう、YouTube Music は Chrome の
**⋮ → キャストと保存と共有 → ページをアプリとしてインストール** で独立ウィンドウにしておく。
アプリウィンドウのタイトルは `YouTube Music` だが、普通のタブは
`YouTube Music - Google Chrome` になるので、既定の許可リストは
`titleNotContains: " - Google Chrome"` でこの2つを分けている。

同じ理屈で、Edge なら `" - Microsoft Edge"` を除外している。

## 記録

セッションと、ブロックされた回数が
`%USERPROFILE%\Documents\detox-pc-log.json` に追記される。

形式はスマホアプリの書き出しと同じなので、このファイルをスマホに送って
アプリの **設定 → JSON を読み込む** から取り込めば、PC とスマホの記録がひとつに並ぶ。

- ブロックされた1回 = 衝動ログ1件（`note` に「PC: ブロック — アプリ名「タイトル」」が入る）
- 同じアプリを続けて掴んでも、記録は60秒に1件までに抑えている

`-LogPath` で保存先を変えられる。

## 制限

- **Windows 専用。** Windows PowerShell 5.1（Windows に最初から入っているもの）で動く
- **管理者権限で動いているアプリは最小化できない。** 情報も取れないので、そういう窓は素通りする
- ストアアプリ（UWP）は前面のプロセスが `ApplicationFrameHost.exe` になり、
  プロセス名では見分けられない。`titleContains` で指定すること
- 全画面のゲームなど、最小化に抵抗するアプリはある
- **テストは許可判定のロジックだけ。** Windows API を呼ぶ部分（前面ウィンドウの取得と最小化、HUD）は
  この環境で実行できていないので、初回は `-DryRun` から試すこと

## 開発

```
pwsh -NoProfile -File tests/matching.tests.ps1
```

Windows API に触らない判定ロジックは `lib/matching.ps1` に切り出してあり、
このテストは Windows 以外でも走る（CI でも実行している）。
