# 日次レポート（`npm run report:daily`）

その日の運用結果をSlackへ自動で投げます。記事の「GitHub Actionsで毎日Slackに報告」と同じ形ですが、
**出す数字を変えてあります**。

## なぜ「今日いくら勝ったか」を主役にしないのか

資産の大半が損切りなしの長期保有なら、市場が上がった日は自動的にプラスになります。
それを毎日眺めても、ルールが効いているのかどうかは永久に分かりません。
詳しくは `docs/stock-trading-automation-review.md` の §1。

そこでレポートは上から順にこう並べています。

1. **ベンチマーク超過** — 当日と開始来。市場の分を引いた残りが実力の候補
2. **ベータ調整後アルファとそのt値** — t値が2未満なら「まだ運と区別できない」と明示する
3. **リスク上限の抵触** — 当日の下落が停止ラインを割ったら最初に目に入る位置に出す
4. 保有銘柄・当日の約定・配当入金

## セットアップ

### 1. Slackの受け口を作る

Slackアプリの **Incoming Webhooks** を有効にし、投稿先チャンネルのWebhook URLを取得します。

### 2. 環境変数

`.env.local`（ローカル）または GitHub の Secrets / Variables に入れます。

| 変数 | 必須 | 既定 | 内容 |
|---|---|---|---|
| `ALPACA_API_KEY` | ○ | — | Alpacaのキー |
| `ALPACA_API_SECRET` | ○ | — | Alpacaのシークレット |
| `ALPACA_PAPER` | | `true` | ペーパー口座を読む。実口座を読むときだけ `false` |
| `SLACK_WEBHOOK_URL` | | — | 未設定ならコンソール出力のみ |
| `BENCHMARK` | | `SPY` | 比較対象 |
| `DAILY_LOSS_LIMIT` | | `0.03` | 当日の下落がこれを超えたら停止を促す |
| `HISTORY_PERIOD` | | `1A` | 評価額履歴の取得期間（`1M` `6M` `1A` など） |

### 3. 実行

```bash
npm run report:daily              # 口座を読んでSlackへ
npm run report:daily -- --demo    # ネット不要。整形だけ確認するダミーデータ
npm run report:daily -- --dry     # 口座は読むがSlackへは投げない
```

## GitHub Actionsで毎日回す

`.github/workflows/daily-report.yml` を用意してあります。

- 実行時刻: `30 21 * * 1-5`（UTC）＝ 米国東部の17:30（夏時間）/ 16:30（冬時間）。どちらも大引け後
- 手動実行も可能（Actions画面の **Run workflow**）
- リポジトリの Settings → Secrets and variables → Actions に
  `ALPACA_API_KEY` / `ALPACA_API_SECRET` / `SLACK_WEBHOOK_URL` を登録

> GitHub Actions の cron はUTC固定です。夏時間の切り替わりで実行時刻が1時間ずれますが、
> どちらの時刻でも大引け後に収まるように設定してあります。
> また、スケジュール実行は混雑時に数十分遅れることがあります。

### ⚠ セキュリティ（ここは飛ばさないでください）

Alpacaは**読み取り専用のAPIキーを発行できません**。レポートのためだけでも、
置くキーは発注できるキーになります。つまり:

**ワークフローを書き換えられる人 ＝ 資金を動かせる人** です。

最低限これをやってください。

1. **ペーパー口座のキーを使う**（`ALPACA_PAPER=true`）。レポートの検証にはこれで十分です
2. 実口座を読むなら、**ブランチ保護**を有効にして `.github/workflows/` の変更にレビューを必須にする
3. さらに **Environment** を作って承認を必須にする（Settings → Environments）
4. Secretsは fork からの PR では渡らない設定のままにする（既定の挙動）

このワークフローは `permissions: contents: read` で動き、リポジトリには何も書き込みません。
コード側も読み取りAPIしか呼びません（`src/report/alpaca.ts`）。

## 既知の限界

1. **Alpacaの口座APIは実口座で検証していません**。開発環境からAlpacaへ到達できなかったため、
   レスポンス形状は仕様ベースです。フィールドが取れない場合は0として扱い、注記に出します。
   初回は `--dry` で数字が妥当か確認してください
2. **アルファのt値は口座の評価額履歴から計算しています**。入出金があった日は評価額が
   ジャンプするため、リターンが歪みます。入出金の直後は数字を鵜呑みにしないでください
3. **休場日**は口座データが更新されないため、その旨を注記に出して当日比は0付近になります
4. 配当は口座の入金記録（Activities）から取っており、税引後の入金額です。
   バックテスト側の配当計算とは税の扱いが揃っていません
5. **観測日数が短いうちは、アルファもt値も動きが激しい**のが正常です。
   3週間程度では意味のある値になりません（これが検討メモの結論そのものです）
