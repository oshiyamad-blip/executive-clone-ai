# 実株価バックテスト（`npm run backtest`）

`docs/stock-trading-automation-review.md` の検討を、合成データではなく**実際の株価**で回すためのツールです。
「−8%損切り / +20%利確」といったルールを、実際の寄値・高値・安値の上で執行して、
ベンチマーク（既定は SPY）に対してどうだったかを出します。

---

## 使い方

```bash
npm install

# 1) ネットワーク不要。エンジンの挙動だけを確認する
npm run backtest -- --selftest

# 2) 実データ。APIキー不要（Stooqから取得し data/prices/ にキャッシュ）
npm run backtest -- --from 2015-01-01 --to 2026-08-01

# 3) 全トレードをCSVに出す
npm run backtest -- --trades data/backtest-trades.csv --json data/backtest.json
```

初回は母集団のぶんだけ日足を取りに行くので数分かかります。2回目以降は `data/prices/` の
キャッシュを読むのでオフラインで動きます。取り直したいときは `--refresh`。

---

## データソース

| provider | APIキー | 配当調整 | 用途 |
|---|---|---|---|
| `stooq`（既定） | 不要 | **なし**（分割調整のみ） | まずはこれ。手軽 |
| `alpaca` | 必要 | あり（`adjustment=all`） | 実運用と同じ配信元で正確に見る |
| `csv` | — | 用意したCSV次第 | オフライン再実行・手持ちデータ |

```bash
# Alpaca を使う場合（.env.local に記入）
ALPACA_API_KEY=...
ALPACA_API_SECRET=...
npm run backtest -- --provider alpaca --refresh
```

**重要**: Stooq は配当を価格に反映しません。配当貴族スリーブは配当が収益の柱なので、
Stooq で回すと**この枠のリターンが実際より低く出ます**。配当込みで正しく見たい場合は
`--provider alpaca --refresh` を使ってください。

CSVを自分で用意する場合は `data/prices/<SYMBOL>.csv` に以下の形式で置きます。

```
Date,Open,High,Low,Close,Volume
2015-01-02,205.13,205.68,203.79,205.43,121465900
```

---

## 執行モデル（ここが実データを使う意味）

日足の OHLC を使い、実際に約定しうる価格で決済します。

1. **判断は終値まで、約定は翌日の寄り。** 判断日の終値では買いません（ルックアヘッド防止）
2. **寄りがバリアを越えていたら寄り成行。** 決算ギャップで −8% の損切りが −8% で止まらないケースを
   `stop_gap` として記録します
3. **同じ日に損切りと利確の両方に触れた場合は、必ず損切りを先に採用。** 日足では前後関係が
   分からないため、楽観側に倒すと成績が過大評価になります
4. 最大保有日数に到達したら終値で手仕舞い（`timeout`）

エンジンの正しさは次のケースで確認済みです。

| ケース | 期待する挙動 | 実際 |
|---|---|---|
| 寄りが −15% に飛ぶ | 損切り価格では約定しない | `stop_gap` / −15.00% |
| 高値 +25% と安値 −10% に同日到達 | 保守的に損切り側 | `stop` / −8.00% |
| 値動きなし | 10日でタイムアウト | `timeout` / 保有10日 |

## 銘柄の自動選定

`--universe` で渡した母集団から、**判定日までのデータだけ**を使って選びます。

| スリーブ | 選び方 | 条件 |
|---|---|---|
| 配当貴族 | 固定（既定 `NOBL`） | 損切りせず持ち切る |
| 中期成長株 | 12-1モメンタム上位 | 200日線超 / 年率ボラ上限 / 平均売買代金20M以上 |
| 短期 | 押し目 | 50日線超だが5日線を下回っている銘柄 |

```bash
# 母集団を差し替える
npm run backtest -- --universe path/to/your-universe.txt

# ルールをいじる
npm run backtest -- --mid-stop 0.10 --mid-target 0.25 --mid-slots 8
npm run backtest -- --short 0        # 短期スリーブを止めて比較する
```

配当貴族枠に個別銘柄を並べず ETF（NOBL）を既定にしているのは、**指数の構成銘柄入れ替えを
織り込むため**です。現在の配当貴族リストを過去に遡って持たせると、途中で脱落した銘柄が
最初から存在しないことになり、成績が実際より良く出ます。

## 出力の読み方

総リターンではなく、**アルファのt値**を見てください。

```
── 実力の検定 ──
  ベータ            0.82
  年率アルファ      3.10%   ※ベータで説明できない部分
  アルファのt値     0.94
  → t値が2未満。この期間の成績は運とルールの実力を区別できない。
```

- **ベータ**: 市場との連動度。0.8なら市場が10%上がると8%上がる。この分は「ルールの実力」ではない
- **アルファ**: ベータで説明できない残り。ここが実力の候補
- **t値**: アルファがノイズと区別できるか。**2未満なら、プラスでも実力の証明にはならない**

「損切りの実際」欄も見てください。ギャップ約定の割合が高いほど、
「−8%で止まる」という前提が実際には成立していないことを意味します。

## 既知の限界

このツールで出た数字を過信しないための注意点です。

1. **生存者バイアス**: 同梱の母集団は現在上場している銘柄の一覧です。過去に遡って使うと、
   破綻・上場廃止・買収された銘柄が存在しないことになり成績が上振れします。
   正しくやるには判定日ごとの構成銘柄（point-in-time universe）が要ります
2. **日足の粒度**: 1日の中の値動きの順序が分からないため、両方に触れた日は保守側に倒しています。
   実際の成績はこれより良いことも悪いこともあります
3. **配当**: Stooq では配当が価格に入りません（上記）
4. **オーバーフィット**: パラメータを何度も変えて一番良いものを選ぶと、その数字は将来を予測しません。
   試した回数を記録し、期間を分けて（前半で決めて後半で検証する）確認してください
5. **PDT規制・信用余力・約定量の制約はモデル化していません**。米国では口座資産25,000ドル未満だと
   5営業日中4回以上のデイトレードが制限されるため、短期スリーブは現実には回らない可能性があります
6. **1回のバックテストは1本の履歴でしかありません**。開始日を数ヶ月ずらすだけで結果は変わります。
   期間を変えて複数回まわし、結論が安定するかを見てください
