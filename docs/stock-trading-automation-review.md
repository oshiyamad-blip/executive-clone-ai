# 検討メモ：ClaudeCodeで株式投資を自動化した記事について

対象: 「ClaudeCodeで株式投資を自動化したら3週間で4.19%勝った」という記事内容の妥当性検討。
作成日: 2026-08-23

---

## 0. 結論（先に3行）

1. **「3週間で+4.19%」は実力の証拠にならない**。この数字はノイズと統計的に区別がつかず（t≈1.0、片側p≈0.16）、
   さらに資産の70%が損切りなしの長期保有である以上、リターンの大半は「相場が上がったこと」の反映。
2. **期待値の算数は正しいが、前提の勝率が根拠なし**。特に**短期ルール（-3%損切り/+9%利確）は期待値マイナス**で、
   シミュレーションでは年率−30%級の毀損要因になる。ここは採用してはいけない。
3. **記事の本当の価値は投資ロジックではなく「判断基準を言語化 → API → 日次Slack報告」という型**。
   この型は自社業務（本リポジトリのテーマそのもの）に転用価値がある。投資は転用先として最も不利な題材。

---

## 1. 「3週間で4.19%勝った」の検証

### 1.1 統計的にはノイズと区別できない

記事の運用は「配当貴族70% + 中期成長株 + 短期株」。この構成の年率ボラティリティを17%と置くと、
3週間（約15営業日）のリターンの標準偏差は **4.15%** になる。

| 想定ボラ（年率） | 3週間の標準偏差 | +4.19%のt値 | 「実力ゼロでも起きる」確率 |
|---|---|---|---|
| 14% | 3.42% | 1.23 | 11.0% |
| **17%** | **4.15%** | **1.01** | **15.6%** |
| 20% | 4.88% | 0.86 | 19.5% |
| 25% | 6.10% | 0.69 | 24.6% |

つまり **+4.19%は「ちょうど1標準偏差」**。実力がまったくゼロのシステムでも、6回に1回はこの成績が出る。

さらに悪いことに、**この差を統計的に確認するには非現実的な時間がかかる**（t=2に到達するまでの必要年数）:

| 真の超過収益(α) | 必要な観測年数 |
|---|---|
| 年3% | 128年 |
| 年6% | 32年 |
| 年12% | 8年 |
| 年20% | 2.9年 |

3週間のデータから年利101%を導く計算は、記事自身が「絶対にありえないけど」と断っている通りだが、
**「3週間ではプラスかマイナスかすら判定できない」**という点はもっと強調されるべき。

### 1.2 ベンチマークとの比較がない

「+4.19%」は絶対収益。同期間にS&P500が+3%上がっていたなら、実力による上乗せ（α）は+1%程度でしかない。
資産の70%が損切りしない長期保有（＝ほぼバイ・アンド・ホールド）である以上、
**市場が上がれば自動的に0.7×市場リターンが乗る**。

評価するなら、報告すべき数字は以下:

- 同期間のSPY（またはNOBL）リターン
- 実際に取ったベータ（現金比率を含む）
- ベータ調整後の超過収益
- 最大ドローダウン、取引回数、勝ちトレード/負けトレードの分布

日次Slack報告を作っているなら、この4つを出す方が「今いくら勝ったか」より遥かに意味がある。

## 2. 期待値ロジックの検証

### 2.1 算数は合っている。しかし「勝率」は選べない

記事の計算はそのまま再現できる。

- 中期: `0.33 × 20% + 0.67 × (−8%) = +1.24%`
- 短期: `0.50 × 9% + 0.50 × (−3%) = +3.00%`

問題は、**利確幅と損切り幅は自分で決められるが、勝率は決められない**という点。
ドリフトゼロ（＝実力ゼロ）の価格過程では、到達確率は理論的に `損切り幅 ÷ (損切り幅 + 利確幅)` になる。

| ルール | ノーエッジでの勝率 | その勝率での期待値 | 記事の前提勝率 | 必要な「実力」 |
|---|---|---|---|---|
| 中期 −8% / +20% | 28.6% | **±0%** | 33% | +4.4pt |
| 短期 −3% / +9% | 25.0% | **±0%** | 50% | **+25.0pt** |

**損切り・利確ルールは期待値を生まない。ルールを守っただけでは期待値はゼロ**（手数料と税を引けばマイナス）。
記事の「期待値さえ合っていれば予測は必要ない」という主張は、正確には
**「+4.4pt（または+25pt）の予測精度があれば予測は必要ない」**と言っている。循環している。

麻雀のたとえで言えば、リーのみでリーチしない判断ができるのは**自分の手牌と相手の捨て牌が見えている**から。
株の勝率は事後にしか分からない。手牌を見ずに期待値表だけ持っている状態に近い。

### 2.2 モンテカルロ検証（20万試行）

幾何ブラウン運動（年率ボラ35%、ドリフトは市場並みの年8%）で各ルールを回した結果:

**中期ルール（−8% / +20%、最大60営業日保有）**

| 損切りの置き方 | 1トレード期待値 | 勝率 | 下位5% | 下位1% |
|---|---|---|---|---|
| ブローカー側にstop注文 | **+0.45%** | 33.1% | −8.00% | −8.00% |
| GitHub Actionsで日次チェック | +1.06% | 39.0% | **−11.30%** | **−12.73%** |

注目点が2つある。

- **勝率33%はほぼ再現された**。ただしそれは実力ではなく、**市場ドリフト＋バリア設計から自動的に出る数字**。
  期待値は記事の+1.24%ではなく**+0.45%**（時間切れ決済と、利確幅ちょうどで抜けられないケースがあるため）。
- **日次チェック方式は期待値が良く見えるが、これはルールを守れていないだけ**。
  下位1%が−8%→−12.7%に悪化しており、テールリスクが1.6倍。「負けない」ことが目的のルールで
  最悪ケースが1.6倍になるのは本末転倒。**損切りは必ずブローカー側のbracket/OCO注文で置くこと。**

**ドリフト感応度（中期ルール、ブローカー側stop）**

| 想定ドリフト（年率） | 1トレード期待値 | 勝率 |
|---|---|---|
| −10% | −1.41% | 26.1% |
| −5% | −0.92% | 28.0% |
| **0%** | **−0.37%** | 30.0% |
| +4% | −0.05% | 31.3% |
| +8% | +0.37% | 32.9% |
| +15% | +1.17% | 35.7% |

**このルールの期待値は、まるごと「米国株が上がり続けるか」に依存している**。
つまり中期ルールは、配当貴族70%とまったく同じリスク（米国株のベータ）を、
より高い回転コストと税負担で買い直しているだけ、というのが実態に近い。

**ボラティリティ感応度（固定%バリアの弱点）**

| 銘柄の年率ボラ | 1トレード期待値 | 勝率 | 平均保有 |
|---|---|---|---|
| 20% | +1.31% | 49.8% | 46営業日 |
| 35% | +0.43% | 33.1% | 24営業日 |
| **50%** | **−0.21%** | 28.0% | 12営業日 |

**「8%で損切り」という固定%は、銘柄のボラティリティ次第で意味が変わる**。
高ボラ銘柄では日常的な値動きで損切りにかかり、期待値がマイナスに落ちる。
実装するなら固定%ではなく**ATR（平均的な値動き幅）の倍数**でバリアを置くべき。

### 2.3 短期ルールは期待値マイナス（最重要）

**短期ルール（−3% / +9%、最大20営業日）**

| 想定ドリフト（年率） | 1トレード期待値 | 実際の勝率 | 記事の前提 |
|---|---|---|---|
| 0% | −0.54% | 20.7% | 50% |
| +8% | −0.44% | 21.6% | 50% |
| +20% | −0.23% | 23.3% | 50% |

**勝率50%という前提が、現実には20〜23%**。損切り幅が狭いほど「普通の値動き」で刈られるため、
3:1のペイオフ比を狙うほど勝率は下がる。コストと税を引いた年率換算では:

```
短期: 税前EV −0.43% → 手数料後 −0.53% → 年間約63回転 → 年率寄与 −33.2%
中期: 税前EV +0.41% → 手数料後 +0.31% → 税後 +0.25% → 年間約10.5回転 → 年率寄与 +2.6%
```

**短期ルールは、3週間の結果がプラスであろうと、採用してはいけない。**
そして中期ルールの年率寄与+2.6%は、ほぼ市場ドリフトの取り分であって、
同じ資金をそのままインデックスに置いても得られる（しかも税の繰り延べが効く分そちらが有利）。

### 2.4 「配当貴族」の説明が事実と違う

記事は配当貴族を「何十年も**株価が**上がり続けている銘柄」と説明しているが、
配当貴族（S&P 500 Dividend Aristocrats）の定義は **25年以上連続で増配している銘柄**であり、株価の話ではない。

そして実績として、**配当貴族は直近10年で市場平均に負けている**:

| | 10年トータルリターン | 年率 |
|---|---|---|
| NOBL（配当貴族ETF） | +157% | 9.69% |
| SPY（S&P500） | +266% | 15.08% |

理由は明快で、この10年の指数リターンを牽引したメガテック（Alphabet、Metaなど）は
増配実績の条件を満たさず配当貴族に入らないため。NOBLのテック比率は3%程度。

**「絶対に負けない企業」という前提そのものが要検証**。配当の安定性は高いが、
それは総リターンを犠牲にして買っている安定性である、というのが正確な理解。

## 3. 自動化する場合の実装論点

投資判断の是非とは別に、「自動発注システムとして成立しているか」の観点。記事には触れられていない必須項目が多い。

### 3.1 執行（ここが一番壊れやすい）

- **損切り・利確はブローカー側のbracket/OCO注文で置く**。cronやGitHub Actionsの日次チェックでは
  ルール通りに約定しない（§2.2でテールが1.6倍に悪化）。Alpacaはbracket order対応。
- **冪等性**。GitHub Actionsはリトライ・重複実行が起きる。`client_order_id` を必ず付けて二重発注を防ぐ。
- **決算ギャップ**。決算跨ぎは−8%のstopが−8%で約定しない。決算日をまたぐポジションを持たないか、
  持つならサイズを落とすルールが要る。
- **PDT規制**。米国では証券口座の資産が25,000ドル未満の場合、5営業日中4回以上のデイトレードは制限される。
  **短期ルールはこれに直撃する**。
- **キルスイッチと上限**。1日の最大発注額、最大ポジション数、1銘柄あたり上限、
  「口座残高が前日比−X%なら全停止」を実装。暴走時の損失上限を設計で決める。

### 3.2 LLMの使い方

- **発注判断をLLMにさせない**。LLMは非決定的で、同じ入力で違う結論を返しうる。
  役割は「候補の抽出」と「判断理由の言語化」までにし、**発注は決定論的なルールコードで行う**。
- **プロンプトインジェクション**。ニュース記事や決算テキストをLLMに読ませる設計にすると、
  外部テキストが指示として解釈されるリスクがある。取引権限を持つAPIキーと同じプロセスに置かない。
- **APIキーの権限分離**。GitHub Actions のsecretsに発注権限のあるキーを置く場合、
  ワークフローの改変権限＝資金の移動権限になる。ブランチ保護とEnvironment承認が必須。

### 3.3 検証プロセス

- **ペーパートレードで最低3ヶ月**、その後少額で3ヶ月、という段階を踏む。
- **バックテストのバイアス**を潰す: ルックアヘッド（当日終値で当日判断していないか）、
  サバイバーシップ（現在の上場銘柄だけで検証していないか）、オーバーフィット（パラメータを何回変えたか記録する）。
- **評価はベンチマーク超過で**（§1.2）。

## 4. 制度・税務（日本居住者の場合）

記事の「日本の証券会社にはAPIがない」という前提は、2026年8月時点では**部分的に古い/不正確**。

| | 米国 Alpaca（alpaca.markets） | アルパカ証券（AlpacaJapan） | 三菱UFJ eスマート証券（旧auカブコム） |
|---|---|---|---|
| 対象 | 米国株・ETF・暗号資産 | 米国株・ETF | 日本株 |
| API | 個人向けREST/WebSocketあり | 24時間取引APIは**金融機関向け**が中心。個人向け自動売買APIの提供可否は要確認 | kabuステーションAPI（個人向けREST、無償） |
| 法人格 | 米国ブローカー | 日本の第一種金商業者（関東財務局長（金商）第3024号） | 日本の証券会社 |
| 特定口座 | なし | あり（源泉徴収あり/なしを取り扱い ※要確認） | あり |
| 口座開設 | 日本居住者の可否は**要確認** | Woodstockアプリ経由 | 通常のネット証券と同様 |

**確認が必要な点**（今回、公式ページへの直接アクセスがネットワーク制限で取得できず、検索結果ベースの情報）:

- 米国Alpacaが現在も日本居住者の新規口座開設を受け付けているか
- アルパカ証券（日本法人）が個人投資家向けに発注APIを開放しているか
  → **開放されているなら、特定口座が使えるぶん米国口座より圧倒的に有利**。ここは最初に確認すべき。

**税務の実務**（米国口座を使う場合）:

- 特定口座がないため、**譲渡損益・配当を自分で計算して確定申告**（申告分離課税20.315%）。
  取引回数が多い自動売買では、この集計作業自体が重い。円換算は約定日レートで行う必要がある。
- 配当は**米国で10%源泉（日米租税条約）＋日本で20.315%**。二重課税分は外国税額控除で取り戻すが、申告が必要。
- 円ドルの為替差損益の扱いも論点になる。
- 短期売買は**利益確定のたびに課税される**ため、長期保有の課税繰り延べメリットを失う。
  §2.3の年率寄与はこれを織り込んだ数字。

**法規制（重要）**:

記事の「このまま資産運用を依頼し続けたら」はジョークだが、**他人の資産を運用すれば金商法の登録が必要**になる。

- 他人の資金を一任で運用 → **投資運用業**の登録
- 助言して報酬を得る → **投資助言・代理業**の登録

無登録営業は刑事罰の対象。社内で「うちの資金でもやってみよう」という話に発展する場合は、
**自己資金（自己勘定）に限る**という線を最初に引いておく必要がある。

## 5. この記事をどう扱うか（推奨）

### 投資ロジックとしては

**現状のまま真似することは推奨しない**。理由は上記の通りで、要点は3つ:

1. 短期ルール（−3%/+9%）は期待値マイナス。**削除一択**。
2. 中期ルールの期待値は市場ドリフトの取り分でしかなく、回転コストと課税でインデックス保有に劣後する可能性が高い。
3. 3週間の成績は判断材料にならない。少なくとも**ベンチマーク超過で、複数の相場局面（下落局面を含む）を通した検証**が要る。

もし続けるなら、最低限の修正:

- 損切り/利確はブローカー側のbracket注文で置く
- 固定%ではなくATR倍数でバリアを設計する
- 短期枠は停止し、その資金はインデックスか現金へ
- 日次Slack報告に「ベンチマーク超過リターン」「最大ドローダウン」「取引回数」を含める
- 全体のリスク上限（日次−X%で全停止）を先に決める

### 「型」としては

一方で、記事が実証している構造そのものには価値がある。

```
判断基準を言語化する → APIに接続する → 毎日Slackに結果を報告させる
```

これは本リポジトリ（経営者クローンAI）がやろうとしていることと**まったく同じ構造**である。
違うのは題材だけで、投資は「結果のノイズが大きく、正解の検証に数年〜数十年かかる」という点で、
**この型を試す題材として最も不利**。

同じ型を、**フィードバックが速く、判断基準が実際に社内に存在する領域**に当てると効果が出やすい。例:

- 与信・取引先審査の一次判定（判断基準が明文化されており、結果が数ヶ月で分かる）
- 採用の書類一次選考（本リポジトリの `npm run hire` が既に該当）
- 稟議・投資判断の事前壁打ち（`npm run decide` が既に該当）
- 案件の受注可否判断（営業ルールの言語化 → 日次レポート）

**社内発信として使うなら**、「株で勝った話」ではなく
**「判断基準を言語化すれば自動化できる。その実例として、あえて一番検証の難しい投資でやってみた」**
という構成にした方が、主張が数字の運不運に左右されずに済む。

## 付録: 検証に使った前提

- モンテカルロ: 幾何ブラウン運動、20万試行、日次ステップ、日中レンジはブラウン橋近似
- 中期ルール: 損切り−8% / 利確+20% / 最大60営業日で時間切れ決済
- 短期ルール: 損切り−3% / 利確+9% / 最大20営業日で時間切れ決済
- コスト: 往復スリッページ0.1%、実現益への課税20.315%
- ポートフォリオ年率ボラ17%（配当貴族70%＋成長株30%を想定）

上記の数値は `node scripts/verify-trading-claims.mjs` で再現できます（乱数シード固定、依存なし）。
