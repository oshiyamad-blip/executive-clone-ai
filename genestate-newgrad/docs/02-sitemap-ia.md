# 02. サイトマップ / 情報設計 と 下層コンテンツ検討

`/newgrad/` 配下の全ページの構成案。
採用トップの各セクションが、どの下層ページへ送客するかまで含めて設計する。

---

## 1. サイトマップ

```
/newgrad/                      新卒採用トップ（本リポジトリで実装済み）
│
├── /newgrad/message/          代表メッセージ
├── /newgrad/about/            ジーンステイトを知る（理念・社名の由来・3事業）
│   └── /newgrad/about/numbers/    数字で見るジーンステイト
├── /newgrad/work/             仕事を知る（職種紹介）
│   ├── /newgrad/work/coordinator/  人材コーディネーター／営業
│   └── /newgrad/work/engineer/     エンジニア（配属先の一つとして）
├── /newgrad/growth/           育成・研修（G-Tech と 1年間の育成体系）
├── /newgrad/people/           社員を知る（インタビュー一覧）
│   └── /newgrad/people/{slug}/     個別インタビュー記事
├── /newgrad/culture/          働く環境・制度・福利厚生
├── /newgrad/requirements/     募集要項
├── /newgrad/flow/             選考フロー
├── /newgrad/faq/              よくある質問
└── /newgrad/entry/            エントリー
```

### 階層を浅く保つ理由
学生は「知りたいことが3クリック以内にあるか」で離脱する。
`/newgrad/` から**全ページに1クリックで到達できる**構造にし、
下層ページ同士も相互に回遊できるよう、各ページ末尾に「次に読む」ナビを固定で置く。

### 中途採用ページとの接続
`/newgrad/` と `/recruit/`（中途）は**相互リンクを1本ずつだけ**置く。
フッターに「中途採用をお探しの方はこちら」を1行。逆も同様。
それ以上つなぐと、学生が中途向けの情報（即戦力要件・年収レンジ）に迷い込んで不安になる。

## 2. 採用トップ `/newgrad/` のセクション構成

**設計思想**：上から順に「掴む → 信じる → 具体を知る → 決める」の4段。
学生の心理は「面白そう（情緒）→ 本当か？（懐疑）→ 自分にできそう（具体）→ 応募しよう（行動）」と動く。
セクション順はこの順序に従っており、**入れ替えると説得の論理が崩れる**。

| # | セクション | 目的 | 主な中身 | 送客先 |
| --- | --- | --- | --- | --- |
| 1 | **MV（メインビジュアル）** | 掴む | キャッチコピー＋人物写真＋「20XX年卒 新卒採用（一期生）」バッジ＋エントリーCTA | `/newgrad/entry/` |
| 2 | **INTRODUCTION** | 掴む→信じる | 社名の由来（Gene × State）を短文で回収し、「育てるを事業にしてきた会社」を宣言 | `/newgrad/about/` |
| 3 | **MESSAGE** | 信じる | 代表メッセージ抜粋。一期生への呼びかけ。顔写真必須 | `/newgrad/message/` |
| 4 | **NUMBERS** | 信じる | 数字で見るジーンステイト（6項目程度） | `/newgrad/about/numbers/` |
| 5 | **BUSINESS** | 具体 | 3事業（IT／人材／BPO）のカード。「どの事業に配属される可能性があるか」を示す | `/newgrad/about/` |
| 6 | **WORK** | 具体 | 総合職一括採用の説明＋配属先職種（人材コーディネーター／営業、エンジニア） | `/newgrad/work/` |
| 7 | **GROWTH** | 具体（最重要） | 入社後1年間のタイムライン、G-Tech、資格支援、フォロー体制 | `/newgrad/growth/` |
| 8 | **PEOPLE** | 具体 | 社員インタビューカード3〜4名 | `/newgrad/people/` |
| 9 | **CULTURE** | 具体 | 働く環境・制度・オフィス。写真中心 | `/newgrad/culture/` |
| 10 | **RECRUIT（募集要項サマリ）** | 決める | 募集職種・初任給・勤務地・選考フローの要約 | `/newgrad/requirements/` `/newgrad/flow/` |
| 11 | **FAQ** | 決める | 頻出の不安を4〜6件、アコーディオンで | `/newgrad/faq/` |
| 12 | **ENTRY CTA** | 決める | 最終エントリー導線。締切・説明会日程 | `/newgrad/entry/` |

### 補助導線
- **モバイル固定CTA**：スクロール量がMVを超えた時点で、画面下部にエントリーボタンを常時表示
- **セクションアンカーナビ**：MV直下に横スクロール可能なアンカーリンク列を置き、
  「育成の話だけ読みたい」学生を最短で送る

### GROWTH セクションを7番目に置く理由
学生が最も知りたいのは「自分が通用するか」であり、その答えは育成体系にある。
ただし**信頼を得る前（＝MESSAGE/NUMBERS の前）に置いても読まれない**。
「この会社は信じられそうだ」と思った直後に置くのが最も効く。

## 3. 下層ページ 個別設計

### 3-1. `/newgrad/message/` 代表メッセージ

**目的**：一期生であることの不安を、経営者が直接引き受ける。

| 構成要素 | 内容 |
| --- | --- |
| タイトル | 「先輩が、まだいない。」（キャッチコピー案②をここで使う） |
| 本文 | 800〜1,200字。以下の4点を必ず含める |
| ①なぜ今、新卒採用を始めるのか | 創業から約10年、未経験者を育てる基盤ができたから、というストーリー |
| ②社名に込めた意味 | Gene × State。「人の素質を見つけて組織にする」 |
| ③一期生に何を期待するか | 型をなぞるのではなく、新卒のかたちを一緒につくること |
| ④一期生に何を約束するか | 経営が直接見ること。先輩がいない分の手当てを具体的に示す |
| 署名 | 代表取締役 小島 大知（顔写真・サイン画像があれば） |

**書く上での注意**：一期生の不安（先輩がいない・制度が未整備）に**先に触れる**こと。
触れずに良いことだけ書くと、学生は「言っていないだけだ」と読む。

---

### 3-2. `/newgrad/about/` ジーンステイトを知る

**目的**：事業内容を「学生が理解できる言葉」に翻訳する。
※ コーポレートの `/about/` `/service/` をそのままリンクするのは**不可**。
BtoBの説明は学生には届かない。新卒向けに書き下ろす。

| セクション | 内容 |
| --- | --- |
| 企業理念 | 「関わるすべての人に幸せを運ぶ。」を、日々の仕事の場面に接続して説明する |
| 社名の由来 | Gene × State の図解 |
| 3つの事業 | 各事業を「誰の、どんな困りごとを、どう解決しているか」の型で説明 |
| ├ IT事業 | 未経験からエンジニアを育て、上場企業・官公庁・大手キャリアの案件へ |
| ├ 人材事業 | モバイル領域の販売職を中心とした人材派遣・有料職業紹介 |
| └ BPO事業 | バックオフィス・カスタマーサポートの業務プロセス受託 |
| 事業のつながり | 3事業が独立ではなく**互いを支えている**構造を1枚の図で。ここが理解の山場 |
| 沿革 | 2016年創業〜現在。新卒採用開始を最新のマイルストーンとして置く |

---

### 3-3. `/newgrad/about/numbers/` 数字で見るジーンステイト

**目的**：主観的な訴求を、客観的な数字で裏づける。

掲載候補（**すべて社内で実数の確認が必要 → `docs/05-data-requests.md`**）：

| # | 項目 | 意図 |
| --- | --- | --- |
| 1 | 設立からの年数（2016年〜） | 一期生の不安に対し「会社自体は新しくない」と示す |
| 2 | 社員数 | 経営との距離の近さ |
| 3 | 平均年齢 | 若い組織であること |
| 4 | 男女比 | 属性の多様性 |
| 5 | 未経験入社の割合 | **最重要**。ペルソナAへの直接の回答 |
| 6 | 入社後の研修期間 | 育成へのコミットの量 |
| 7 | 取引先の業種内訳 | 仕事の規模感 |
| 8 | 資格取得支援の対象資格数／取得者数 | 育成の実効性 |

⚠️ **「離職率」「定着率」は初年度は載せない。** 新卒の実績がまだ無い状態で
全社の数値を載せると、新卒の数字だと誤読される。

### 3-4. `/newgrad/work/` 仕事を知る

**目的**：「総合職一括採用」の不安（何をやるか分からない）を解消する。

一括採用は学生にとって**不安要因**である。「配属ガチャ」という言葉が定着している以上、
「入社後に決まります」だけで終わらせると確実に離脱する。以下で回収する。

| セクション | 内容 |
| --- | --- |
| なぜ総合職一括採用なのか | 会社側の意図を正直に書く。「入口で決め切らなくていい」という**学生側のメリット**として提示 |
| 配属はどう決まるのか | 決定時期・本人の希望の反映方法・面談の有無を**明記する**。ここを曖昧にしない |
| 配属先となる職種 | 下記2職種へリンク |
| キャリアパス図 | 入社1年目→3年目→5年目。職種転換の可能性も図に含める |

#### `/newgrad/work/coordinator/` 人材コーディネーター／営業
- 1日のスケジュール（時系列で）
- 実際の業務の流れ：求職者との面談 → 企業への提案 → 就業後のフォロー
- **やりがいと、しんどさの両方**を書く（しんどさを書くページは信頼される）
- 数字の持ち方（目標設定の考え方）。ここを隠すと不信を招く
- 先輩社員の声へリンク

#### `/newgrad/work/engineer/` エンジニア
- G-Tech研修 → 案件参画までの道筋
- 携わる領域：Webシステム／アプリ開発、サーバ・ネットワークの設計構築・運用保守
- 文系・未経験からの入社事例
- `/newgrad/growth/` へリンク

### 3-5. `/newgrad/growth/` 育成・研修 ★最重要ページ

**目的**：「未経験でも大丈夫」を、**カリキュラムの実物で証明する**。
このページの厚みが新卒採用サイト全体の勝敗を決める。

| セクション | 内容 |
| --- | --- |
| 入社後1年間のタイムライン | 4月入社〜翌3月までを月単位の図に。何を学び、いつ現場に出るか |
| 新入社員研修（全職種共通） | ビジネスマナー、事業理解、同期でのグループワーク |
| G-Tech（エンジニア志望者向け） | 自社開発の未経験者向け育成プログラム。**カリキュラムの実物を出す** |
| ├ 学習範囲 | Java の基礎文法から体系的に。JavaScript / SQL / Linux / PHP など |
| ├ 学習形式 | オンライン研修。講師とチャットで常時つながる環境 |
| └ 同期との接点 | 研修受講者同士の定期Webミーティング |
| コーディネーター職の育成 | 同行同席 → ロールプレイ → 独り立ちまでの段階設計 |
| 資格取得支援 | 対象資格・支援内容（受験料補助・報奨金など） |
| フォロー体制 | 誰が、どのくらいの頻度で、何を見てくれるのか。**担当者の顔写真を出す** |
| 研修中の1日 | 時系列で。**研修風景の写真必須** |

**設計上のポイント**：「充実した研修制度」という言葉は使わない。
代わりに**週次のカリキュラム表を1枚載せる**。言葉より表のほうが信じられる。

### 3-6. `/newgrad/people/` 社員を知る

**目的**：一期生の不安（誰と働くのか分からない）に、実在の人物で答える。

**初年度の制約**：新卒入社の社員がまだいない。
→ **「新卒社員の声」ではなく「若手・未経験入社社員の声」として構成する。**
  これを新卒の声のように見せるのは不誠実であり、必ず属性を明記する。

#### 掲載したい人物（4名を推奨）

| # | 人物像 | 何を語ってもらうか |
| --- | --- | --- |
| 1 | **未経験からエンジニアになった若手社員** | 入社時の不安、G-Techで何が一番大変だったか、初めて現場に出た日のこと |
| 2 | **人材コーディネーター／営業の若手社員** | 求職者の人生に関わる瞬間の話、数字との向き合い方 |
| 3 | **新卒採用の企画担当者（人事）** | なぜ新卒採用を始めるのか、一期生をどう迎えるつもりか。**一期生の不安に最も直接効く** |
| 4 | **管理職・現場のリーダー** | どんな人と働きたいか、若手をどう見ているか |

#### 個別記事 `/newgrad/people/{slug}/` の構成
- プロフィール（氏名／所属／入社年／前職・出身学部）
- 入社理由
- 現在の仕事
- **一番大変だったこと**（← ここが読まれる。成功談だけの記事は読み飛ばされる）
- 学生へのメッセージ
- 1日のスケジュール
- 写真：ポートレート1枚＋業務中カット2枚

### 3-7. `/newgrad/culture/` 働く環境・制度

| セクション | 内容 |
| --- | --- |
| オフィス紹介 | 新宿アイランドタワー5階。**写真中心**。通勤・立地の魅力も学生には効く |
| 制度・福利厚生 | 一覧表で。休暇制度、各種手当、資格支援、リモート可否 |
| 1週間の働き方 | 平均的な出社・在宅の組み合わせ、残業の実態 |
| 社内イベント | 懇親会、表彰、勉強会など。写真 |
| 同期・チームの雰囲気 | スナップ写真中心 |

⚠️ 制度は**実在するものだけ**を書く。学生は入社後に必ず検証する。

### 3-8. `/newgrad/requirements/` 募集要項

| 項目 | 備考 |
| --- | --- |
| 募集職種 | 総合職（職種一括採用） |
| 対象 | 20XX年3月卒業見込みの方 ／ 既卒可否を明記 |
| 初任給 | **必須**。学生が最初に見る項目 |
| 諸手当 | 通勤手当、住宅手当、時間外手当の扱いなど |
| 昇給・賞与 | 回数と実績 |
| 勤務地 | 本社および配属先。**配属先が客先になる可能性は明記する** |
| 勤務時間 | 実働時間・フレックスの有無 |
| 休日休暇 | 年間休日数 |
| 保険 | 各種社会保険 |
| 採用予定人数 | 一期生の規模 |
| 応募方法 | エントリーページへ |

⚠️ **技術者派遣・人材派遣という業態上、勤務地が客先になり得ることは必ず明記する。**
入社後ギャップの最大要因であり、ここを曖昧にすると早期離職に直結する。

### 3-9. `/newgrad/flow/` 選考フロー

- ステップ図（エントリー → 説明会 → 一次面接 → 適性検査 → 最終面接 → 内定）
- **各ステップで何を見るのかを明記する**（学生の準備を助ける＝志望度が上がる）
- 所要期間の目安
- オンライン／対面の別
- 服装の指定
- 内定後のフォロー（内定者研修・懇親会の有無）

### 3-10. `/newgrad/faq/` よくある質問

カテゴリ分けして掲載。**一期生ならではの不安に正面から答える項目を必ず入れる。**

| カテゴリ | 質問例 |
| --- | --- |
| 応募について | 学部・学科の制限は？ 既卒でも応募できる？ 留学等での卒業時期のずれは？ |
| 一期生について | **新卒の先輩がいないが不安。同期は何人？ 誰が面倒を見てくれる？** |
| 仕事について | 総合職の配属はいつ・どう決まる？ 希望は通る？ 勤務地は？ |
| 未経験について | 文系でもエンジニアになれる？ PCスキルはどの程度必要？ |
| 研修について | 研修期間は？ 内容は？ ついていけなかったらどうなる？ |
| 制度について | 残業は？ リモートは？ 転勤は？ |

### 3-11. `/newgrad/entry/` エントリー

- 応募フォーム（WordPress: Contact Form 7 / Snow Monkey Forms 等、既存サイトの実装に合わせる）
- 必須項目は最小限に（**項目が多いほど離脱する**）：氏名／大学・学部／卒業年月／連絡先／志望職種の希望／自由記入
- 個人情報の取り扱いへの同意チェック
- 送信後の自動返信メール文面も併せて用意する
- ⚠️ 就活ナビサイト（マイナビ等）を併用する場合は、そちらへの導線も併記

## 4. リリースのフェーズ分け

全部そろってからの公開は待たない。**採用広報は早いほうが有利**。

### Phase 1（初回公開・本リポジトリの実装範囲）
- ✅ `/newgrad/` 採用トップ（全セクション。中身は確定分から）
- 募集要項・選考フロー・FAQ・エントリー（**この4つが無いと応募が受けられない**）
- 代表メッセージ

### Phase 2（公開後2〜4週間）
- 育成・研修ページ（★最重要。ここが遅れると説明会で口頭補足する羽目になる）
- ジーンステイトを知る／数字で見る
- 仕事を知る（職種2ページ）

### Phase 3（選考開始まで）
- 社員インタビュー（4名）
- 働く環境・制度

### Phase 4（内定後・翌年度に向けて）
- 一期生の内定者インタビュー
- 入社後は「新卒1年目の声」に差し替え、`/newgrad/people/` の主役を新卒に移す
